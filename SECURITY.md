# Security Policy

## Reporting a vulnerability

Please do not disclose security vulnerabilities in a public issue.

For repositories that support it, use GitHub's private vulnerability reporting or a private security advisory. If that option is not available, contact the organization owner through GitHub and include Security report in the subject.

Include:

- the affected repository, version, and environment
- a concise impact assessment
- reproducible steps or a proof of concept
- a suggested mitigation, if known
- only the minimum evidence required

Do not include credentials, access tokens, personal data, or production data.

## Response and disclosure

We aim to acknowledge reports within 3 business days, triage them within 7 business days, and coordinate a fix and disclosure timeline with the reporter. We may ask for a safe reproduction or additional evidence.

Please allow a coordinated disclosure window. We will credit reporters who follow responsible disclosure and request attribution.

## Supported versions

Security support follows the default branch and the latest published release unless a repository states otherwise.
